# Lessons — 2026-11-09（五题 v3/v4 盲测复盘）

## 1. 评分口径必须两层
- v3：19 criteria × 4 subchecks = 76；4/4 才得 5 分，否则该 criterion 0；机器满分 95 + C20 5。
- 200 分制：40 criteria ×5，硬门（manifest、5 checkpoints、PDF 引用、19 个 v3 criterion 全过）任一不过为 0；平台映射 /2。
- v4：在 v3 上按工作场景缺口每项 −5（缺 validation、缺逐记录、缺引用、缺 trust 修复、缺窗口/不变量等）。
- 结论：只报“总分”会掩盖硬伤；必须同时报 criteria 失败数、硬门、v4 扣项。

## 2. 难度门槛拆成两个条件
- 分数 ≤50 与（net_time > 2400s 或 verified_steps ≥50）必须同时满足。
- 小数据题容易在 20–30 分钟跑完；需要全量大文件（如 6.8M 行）或多阶段 S6–S15 才可能过时长。
- 不能把“阶段多”当成难度；要有逐记录输出与真实计算。

## 3. 环境/交付是最常见失败源（非模型能力）
- 平台拒 zip：必须准备拆包 + DELIVERY_MANIFEST。
- 豆包工作模式偶发：+ 菜单打不开、标签页被重定向、textarea 可写但不提交；需 URL 校验与多阶段重试。
- 单题单会话、S1–S5 分段、每段 ≤4 文件 + checkpoint，可显著降低“一次性丢整题”的失败率。

## 4. 参考解质量比数量重要
- 反面案例：review_memo 85 字节、validation 期望值写错（90,594 vs 84,396）、引用无关 PDF、缺逐行/逐支付/库存流水。
- 修正：补 STANDARD-ANSWER、逐记录账本、异常分析，引用对应 PDF 页码，grade 仍保持 76/76。
- 占位 digest（1111/2222/3333）可用于合成题，但必须在题面标明 synthetic，且不要伪装成真实摘要。

## 5. 平台字段与分类
- “行业 L1/L2”与“职业簇 L1/L2”是两套分类，不能混填。
- 职业簇示例：平台、基础设施 / 数据工程与开发 / 安全工程；岗位示例：基础设施工程师、数据库运维/DBA、安全平台工程师、研发效能工程师。
- 行业示例：科技、软件与数字基础设施；企业软件与 SaaS / 互联网平台与数字产品 / AI 与数据技术 / 硬件、半导体、云与。

## 6. 提交前必须核对的 12 项
1 来源授权；2 契约/preflight；3 rubric/参考；4 分数 ≤50；5 时长/步数；6 有效运行；
7 负向/替代；8 C20；9 MANIFEST；10 平台上传；11 诚实报告；12 材料隔离。
- 1/8 是外部签核，不能由作者代签；5 需真实运行证据；10 需端到端试交。
